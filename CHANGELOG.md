# Changelog

All notable changes to LoadTruth are documented here.

## [Unreleased]

### Fixed
- **Equal-height KPI cards.** `StatCard` is now a full-height flex column with the sub-line pinned to the bottom (`mt-auto`), and the Overview KPI grid stretches its items, so all four tiles match height whether or not they carry a progress bar. The Billing KPI row equalizes the same way.
- **Overview "Highest value to review" no longer leaves a gap.** The panel listed only over-called drafts (often just 2-3 rows) while stretching to the full column height. It now ranks every draft ticket by dollar delta (over-calls first, then no-exposure drafts shown in muted text), so the panel fills its space and is the real review queue.
- **Billing "Billed amount by month" single-period view.** The lone floating bar (which read as a glitch when only one month is invoiced) is replaced with a clean single-period panel: the month, the amount, a "First invoiced month" chip, and a full-width baseline track, with a note that a trend appears as more periods are invoiced.
- **Guide uses the full screen.** Dropped the centered `max-w-6xl` column; the intro and step cards span full width and the reference sections tile two-up (`xl:grid-cols-2`, `items-start`) on wide screens, reading top-to-bottom in one column when narrow.

### Added
- **Showcase: product-features and sourced case-studies sections.** The public `/showcase` page now presents the product surface judges should see (multi-tenant isolation, the money frame, reporting and exports, billing and invoicing, the grounded AI analyst, and the evidence receipt + re-verify) and a case-studies grid where every figure (107M CY cleared in 2024, the $190M Miami-Dade monitoring contract, 500%+ of capacity in a post-Katrina audit, the $716K DOJ load-slip fraud, 15M+ CY after Sandy, ~$2B in FL reimbursement) links to its primary source (FEMA, DHS OIG, DOJ, Miami-Dade). The stats band and feature cards use per-item color accents (colorful but simple). All figures are paraphrased from government reports with a compliance note.
- **Friendly, non-gendered member avatars on the login screen.** The two-letter initials are replaced with a small set of varied person glyphs (user-round, circle-user-round, contact-round, smile, user-star) assigned deterministically per member with a color from the chart palette, so the member list reads as human and varied without labeling anyone by gender.

### Added
- **Edit for trucks and sources (CRUD completeness).** Both the certified-truck registry and the evidence-source list could be created and deleted but not edited, though the backend `PATCH` endpoints and the `update` mutations were already wired. Added an Edit action to every truck row (opens the add/edit modal pre-filled; changing capacity re-values matching loads on their next calculation) and to every source row (rename, pause/resume, and update config in a modal). Destructive deletes already use a confirmation modal across trucks, sources, and users; that is unchanged.
- **Source config PATCH now shallow-merges.** `SqlTicketRepository.update_source` merges the incoming config into the stored config instead of replacing it, so an edit that omits a write-only secret (the UI never receives one, so it cannot resend it) preserves the stored value; an explicit empty string clears a key. New test covers both.

### Added
- **Detailed AI analysis per pipeline phase.** Each stage in the pipeline trace (Review console and AI Pipeline screen) now shows a few sentences of plain-language analysis when expanded, not just the one-line summary: what SAM segmented and how the clip was sent, what Muse Spark read or classified and its confidence, how the deterministic geometry turned masks into a fill percent, why an anomaly did or did not fire, and that the valuation is exact arithmetic rather than a model output. Composed client-side in `pipeline-trace.tsx` from the stage's own reported facts, so it works for every existing ticket with no backend change.
- **Showcase linked from the login screen.** The public `/showcase` page is now reachable before sign-in: a "View the public showcase" link in the brand panel footer and a "See the public showcase" link under the sign-in button (so it is visible on mobile too).
- **Overview breakdowns.** The Overview adds a decision-mix, debris-class, and anomaly-severity breakdown row (labeled proportional bars from the event's real counts) under the exposure trend, so the screen is more informative at a glance.

### Changed
- **Trucks and Guide use the full screen.** Both pages were capped to a narrow column (`max-w-[1100px]` / `max-w-4xl`); they now run fluid (`max-w-6xl` for the Guide's reading column) so the content uses the available width on a desktop monitor.
- **New Ticket page no longer leaves a white gap.** The left capture column now carries a "what happens to your clip" explainer and an "event at a glance" stats strip, and a flex spacer absorbs any remaining height, so the column balances the ticket list on the right instead of ending with empty space.

### Added
- **Evidence receipt and Re-verify (Winner.md B5).** A new `POST /tickets/{id}/reverify` reproduces a ticket's fill % from its stored SAM masks by re-running the deterministic Stage-5 geometry offline, and rebuilds an **evidence receipt**: a SHA-256 over every pinned input (clip content hash, a hash of SAM's stored output, the measured mask areas, the placard read, the debris class, the capacity and rate, the fill/volume/dollar result, and the model versions). Same evidence, same number, same fingerprint. New `backend/app/pipeline/receipt.py` (pure), `SqlTicketRepository.reverify_ticket`, and a Reproducibility card in the review console (`frontend/src/components/console/reproducibility-card.tsx`) with a "Re-verify from evidence" button that shows the matched fill % and the receipt hash.
- **Judge mode (Winner.md B7).** `NEXT_PUBLIC_APP_MODE=judge` opens the console on the headline over-call (the highest flagged dollar-delta ticket, or a pinned `NEXT_PUBLIC_JUDGE_TICKET_ID`), sorted by delta across all statuses, and shows a "Run live" control that re-ingests the exact stored clip through the real pipeline. A "bypass cache" toggle adds `?bypass_cache=true` to ingest, which skips both the process-local result cache and the durable per-stage cache so the vision models actually run again, proving the demo is live. New `frontend/src/lib/app-mode.ts`; `bypass_cache` query param on `POST /events/{id}/ingest`; build args threaded through the frontend Dockerfile and compose.
- **Public showcase page (Winner.md B6).** A no-login `/showcase` route: the one-line pitch, a stats band (107M CY, $190M contract, ±10 point target, one phone vs a $50K gantry), the seven-stage anatomy, the two personas on opposite sides of one ticket (tower monitor and county finance director), a "how we measure accuracy" card that separates benchmark accuracy from agreement with the monitor, a constraint-we-hit note, and an honest Working / In progress / Roadmap status. `AuthGate` gained a public-path allow-list so the route renders signed out.
- **Known-volume benchmark harness (Winner.md B1).** New `backend/app/bench/` runs the real pipeline over `data_bench/ground_truth.csv` (clip, true_fill_pct, material, angle, lighting) and reports MAE, RMSE, the share within 10 points, and the error broken down by material, angle, and lighting to `data_bench/results.json`. Pure statistics in `harness.py`; the pipeline runner in `run.py`; `scripts/benchmark.sh` wraps it (`MOCK_AI=1` for a zero-credit dry run). This is the independent accuracy number, kept distinct from monitor agreement.
- **Demo precache script (Winner.md B8).** `scripts/precache-demo.sh` ingests the demo clips once so each clip's SAM + Spark stage results and evidence media land in the durable store (the `AIStageResult` table and the evidence dir, both on volumes that survive a container rebuild), so the demo arc then replays from cache with no model call.

### Changed
- **The circular "accuracy" label is now "Agreement with monitor" everywhere user-facing (Winner.md B3).** The metric that compares the machine fill to the monitor's own call is relabeled across the overview dashboard, the audit packet ("Agreement with monitor" statement), the analyst answers and starter prompts, the assistant chat empty state, and the guide, each clarifying it is agreement with the human reviewer, not benchmark accuracy against a known volume. The internal field name (`accuracy_within_10pct`) is unchanged; the schema docstrings now point at `app.bench` for the independent benchmark. Removed the vestigial `benchmark_accuracy_within_10pct` keys from the seed.
- **The `hollow_load` anomaly is renamed `surface_depth_mismatch` (Winner.md B16).** It now reports exactly what it measures: the load surface spans most of the bed opening while the measured depth is low. No claim of seeing interior voids. Updated the enum, rule text (em dash removed), mock narration, fixture label, seed rows, the frontend type-title map and derived-anomaly fallback, and the README. The threshold constants are unchanged (`_SURFACE_COVERAGE = 0.80`, `_LOW_DEPTH_FILL_PCT = 45`).

### Added

- **Media-size & API-cost optimization layer (keeps the 7 stages intact).** New `pipeline/media.py` centralizes the decisions the Meta Model API limits require (dev.meta.ai/docs): inline up to 50 MB vs. Files-API upload up to 1 GiB with a reusable `file_id`; **upload once, reference across all three per-clip model calls** (SAM track + Spark OCR + Spark classify) so bytes travel once not three times; a 50-image VLM budget with a small set of evenly-spaced, **downscaled** keyframes (1024 px longest edge) for OCR/classify; and a 413 for clips over 1 GiB.
