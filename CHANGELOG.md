## [Unreleased]

### Fixed
- **Floating AI Analyst launcher no longer hides page content.** The fixed bottom-right launcher could sit over the last rows of a scrollable area (the billing invoice total, the reports ledger, the overview review list, admin/pipeline panels). Rather than move or hide the button (fragile, it would dodge different content per page), scrollable regions now reserve bottom space so their last content always scrolls clear of it, the standard chat-widget pattern. New `lt-fab-safe` utility in `globals.css` driven by `--lt-fab-size`/`--lt-fab-gap`/`--lt-fab-clear` variables that describe the launcher geometry in one place (and respect the mobile safe-area inset); applied to the main scroll region on Billing, Reports, Overview, Console queue, New Ticket, Guide, Admin, and AI Pipeline. Replaces the ad-hoc `pb-20` on the review workspace rail.
- **Exports no longer bounce to sign-in.** The Invoice, Print/PDF, Export CSV, and Audit packet actions were plain `<a href>` links to the backend, which can't carry the bearer token, so the backend returned 401 and the app redirected to login in a new tab. Added `openAuthedExport` in `frontend/src/lib/api.ts`: it fetches the document with the Authorization header, wraps the response in a blob URL, and opens it in a new tab (or downloads the CSV). The tab is opened synchronously on the click so it isn't treated as a blocked popup. Wired it into the Billing page (invoice), the Reports page (CSV + audit packet), the console event actions, and the command-palette CSV action; removed the now-unused `exportCsvUrl`/`auditPacketUrl`/`invoiceUrl`/`combinedInvoiceUrl` URL helpers. Verified live: clicking Print/PDF opens the invoice from a `blob:` URL instead of the sign-in screen.

### Added
- **Billing section (what the county pays the contractor).** A new Billing screen and backend billing layer turn reviewed loads into an invoice.
  - **Backend billing roll-up** (`backend/app/tickets/billing.py`): pure, deterministic functions over the domain tickets that reuse the per-ticket dollars from `money.py` (no new math). Each load's *payable amount* is the monitor-called value when a monitor has made a call, otherwise LoadTruth's machine estimate, so drafts still show an expected amount. `build_summary` returns totals (amount due, settled vs. pending), line items grouped by debris class (count, cubic yards, rate, amount), and a month-by-month billing history. Settled = loads a monitor confirmed/overrode; pending = drafts/disputed billed at the current estimate.
  - **Billing API** (`backend/app/api/billing.py`, registered in `app/main.py`): `GET /events/{id}/billing` (per-event invoice roll-up), `GET /billing` (combined across every event the tenant owns), and printable HTML invoices `GET /events/{id}/invoice.html` + `GET /billing/invoice.html` (print to PDF). Read-only and tenant-scoped; 404 on an unknown event.
  - **Printable invoice** (`invoice_html` in `backend/app/tickets/export.py`): a self-contained, styled HTML invoice (header + invoice number, bill-to, line-item table with a total row, settled/pending/amount-due totals, and a plain statement of how loads are billed). Zero-dependency; the browser's Print to PDF produces the filable document, mirroring the audit-packet pattern. No em dashes or build-state language (ui-copy rule).
  - **Billing schemas** (`BillingLineOut`/`BillingPeriodOut`/`BillingSummaryOut` in `backend/app/tickets/schemas.py`).
  - **Billing screen** (`frontend/src/app/billing/page.tsx` + `components/billing/billing-panel.tsx`): headline KPIs (amount due, settled, pending, credited volume), a billed-amount history area chart, a by-debris-class ranked-bar breakdown, and the full invoice line-item table with a total row. Per-event by default; a "This event / All events" scope toggle for admins (combined invoice). "Invoice" and "Print / PDF" buttons open the printable invoice. New `Billing` nav entry; `api.eventBilling`/`combinedBilling` + `invoiceUrl`/`combinedInvoiceUrl` helpers and a `useBilling` hook; monitor-call/status writes now invalidate billing.
  - 30 new backend tests (`backend/tests/test_billing.py` math + `test_billing_api.py` routes, incl. settled-amount tracking a monitor confirm). Gates green: ruff clean, mypy --strict clean on the new modules, pytest 202 passed (was 172); frontend prettier/eslint/tsc/vitest 18 + `next build` ✓ (new `/billing` route).

### Added
- **Live Meta Model API pipeline.** Adding a real `MODEL_API_KEY` to `.env` now runs SAM 3.1 and Muse Spark end to end; without a key the fixtures still run at $0. New `app/ai/live.py` (client), `meta_http.py` (httpx transport with retries and typed errors), `sam_measure.py` (SAM output to bed and load geometry via Meta's `meta-sam-parser`), `pricing.py` (per-call cost), and `pipeline/transcode.py` (ffmpeg resamples and downscales clips before sending). The spend cap now blocks new runs. `make live-check [CLIP=…]` verifies a key and runs one clip live. 33 new backend tests against a fake Model API.

### Added
- **LLM query-economy layer for the Spark/analyst calls.** New `ai/request_params.py` builds the economical `/responses` request shape per task from the admin's per-task config + task-appropriate output caps: perception calls (OCR/classify) cap output at 64 tokens, anomaly narration at 120, the analyst at 512 — never the 4000-token default (output is the costliest token class at $4.25/1M). Combined with the existing per-task reasoning-effort defaults (OCR→low, narrate→minimal) this bounds every query to Meta. New config knobs: `spark_perception_max_output_tokens`, `spark_narrate_max_output_tokens`, `analyst_max_output_tokens`.
- **Media-size & API-cost optimization layer (keeps the 7 stages intact).** New `pipeline/media.py` centralizes the decisions the Meta Model API limits require (dev.meta.ai/docs): inline up to 50 MB vs. Files-API upload up to 1 GiB with a reusable `file_id`; **upload once, reference across all three per-clip model calls** (SAM track + Spark OCR + Spark classify) so bytes travel once not three times; a 50-image VLM budget with a small set of evenly-spaced, **downscaled** keyframes (1024 px longest edge) for OCR/classify; and a 413 for clips over 1 GiB. Stage-1 frame sampling (`frames.py`) now hard-caps keyframes at `max_sampled_frames` so a long clip can't blow the per-frame SAM cost. New config knobs (`media_inline_max_bytes`, `media_upload_threshold_bytes`, `spark_max_images_per_request`, `spark_frames_per_task`, `max_sampled_frames`, `frame_downscale_longest_edge`), 10 new tests, and a LEARNINGS §5 write-up of the limits + strategy. No change to the pipeline stages or the mock path.
- **Mock clip upload now works with steerable positive/negative scenarios.** Fixed the upload failure (an unguarded frame-decode on a real/corrupt video threw a 500); Stage-1 sampling is now wrapped and a bad file returns a clear 400. Added scenario steering: a `scenario__clip.mp4` filename prefix forces a specific mock fixture, so demos can show each path on demand — `clean-full-cd` / `clean-partial-veg` (clean draft), `low-confidence-placard` (unreadable ID), `hollow-load`, `uncertified-truck` (anomaly), and `no-truck` (422, no ticket). Ordinary uploads still deterministically draft a believable clean ticket. New backend tests cover each path.
- **Per-status upload error handling.** `upload()` now parses the backend `detail`, and the New Ticket page maps each status to a clear message (400 unreadable file, 403 permission, 404 missing event, 422 no truck, 503 AI unavailable) instead of one hardcoded "no truck" line. The pipeline run is wrapped so an unexpected failure is a clean 500/503, never a stack trace.
