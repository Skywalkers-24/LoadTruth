## [Unreleased]

### Added
- **Multi-theme system (6 curated dark themes, Material-grounded).** Replaced the binary dark/light toggle with a dark-theme palette driven by `data-theme`, all following Material Design's dark-theme guidance (dark `#121212`-family surfaces with lighter-overlay elevation, desaturated 200-tone accents, high-contrast text): **Midnight** (violet, default), **Graphite** (teal), **Abyss** (cyan), **Evergreen** (green — OK/status shifts to teal so it never collides with the primary), **Plum** (rose), **Enterprise** (professional dark navy + corporate blue, tighter radius). New `lib/theme.tsx` catalog (`THEMES`, `ThemeMeta`), flash-free pre-paint script migrates old `"dark"/"light"/daylight/classic/arctic"` prefs onto the new ids. `ThemeToggle`/`ThemePicker` dropdown with live color swatches (flat list, no scheme grouping); also on the **login screen**; the command palette lists all themes. New `PaletteIcon`.
  - _Superseded the earlier light/dark set (Daylight/Classic/Arctic removed) per design review; `toggle()` now cycles through the catalog._
- **Expandable AI pipeline stages.** `PipelineTrace` rows are now click-to-expand (previously a static list that couldn't open): each stage reveals status, model, confidence, and the previously-hidden `duration_ms`. Works on the Review Console and the `/pipeline` page.
- **Floating AI-analyst chat widget.** New `AssistantWidget` (website-style launcher → compact chat panel) mounted on the **Review Console** and **Reports**, so the grounded analyst is a click away without leaving the page. Chat logic extracted into a reusable `useAssistantChat` hook + shared `AssistantChat` component; the `/assistant` page now reuses them. Follow-up suggestions and grounded tool chips surfaced in both.
- **Reports summary now carries `benchmarked_count`** (tickets with a monitor call — the accuracy denominator), so the "All events" view weights combined fill-accuracy exactly instead of approximating by ticket count. Threaded through `ReportsSummaryData` → `ReportsSummary` schema → API → frontend type + aggregation.

### Changed
- **Replaced the muddy amber "money" accent across the app.** The old gold/amber (`#fbbf24` / `#a16207`) read as a sad mustard on the dark canvas. Every theme now uses a clean, bright gold (`#ffca62` family) for the money/variance token (`--money`, `--money-strong`, `--money-soft`) and its chart series. Because the accent is fully tokenized, the flagged-exposure hero, the fill gauge, the ledger deltas, the pipeline value, and the chart line/area all recolor together.
- **Fill accuracy is now computed from real data, not seeded.** `accuracy_within_10pct` (dashboard, reports, audit packet, analyst `accuracy_stats`) is the fraction of tickets whose machine `est_fill_pct` is within ±10 points of the human monitor's call, over the tickets that have a call. Removed the `_SEED_ACCURACY` map / `set_seed_accuracy` / `_accuracy_for_event` and the `benchmark_accuracy_within_10pct` seed wiring. Audit-packet copy updated to describe the real measure. Dashboard/reports tests now recompute the expected value from live ticket data instead of asserting a hard-coded `0.9`.

### Fixed
- **Theme picker didn't switch themes.** The dropdown rows were raw `<button>`s inside the Radix `DropdownMenuContent`, so Radix's menu focus/keyboard management swallowed the click and selection never fired. Rebuilt the rows as real `DropdownMenuItem`s with `onSelect`, which is the pattern that actually applies the theme and closes the menu.
- **Reports ledger → Review Console opened the wrong ticket.** The console only read `?ticket=` once on mount, so client-side navigations were ignored; it now reacts to the search param via `useSearchParams` (wrapped in a `Suspense` boundary). Same class of bug fixed in the notifications popover (rows were dropping the ticket id and landing on `/console`).
- **Cross-tenant leak in `/system/jobs` and `/system/jobs/ticket/{id}`.** Both read a process-global job store with only a "logged-in" check; now scoped to the caller's tenant (`list_jobs` filters to owned events; `job_for_ticket` verifies ticket ownership via the repository).
- **Pipeline trace stage order:** "Flag anomalies" (Stage 6) and "Value the load" (Stage 7) were appended in reverse; the persisted/returned trace now reads in pipeline order.
- **Decimal-zero truthiness bugs:** a legitimate `$0` delta rendered as "unknown" in the analyst's `query_tickets`/`disputes` (now `is not None`); a `0%` monitor call fell back to the estimate on confirm/override (`set_status`, now explicit `None` check). `export.csv` now 404s on an unknown/other-tenant event instead of returning an empty `200`.
- **Frontend robustness/UX:** `useAssistantChat` SSE handlers now update messages immutably (prevents dropped/doubled tokens under React 19); `streamChat` guards `JSON.parse` and anchors the SSE `event:`/`data:` regexes; reports ledger "Measured" column sorts by measured volume (was fill-%) and null deltas sink to the end on either sort direction; console clears the requested-ticket pin once it appears on-page and clamps the page offset when the list shrinks; `review-actions` C/O/D shortcuts no longer fire while a dialog is open; `ConfirmDialog` traps focus; `EventProvider` context value is memoized. Command-palette "Theme" group is now rendered.
- **Admin surface (frontend `/admin`)** on top of the admin APIs: event rate-table editor ($/CY per debris class), certified-truck registry (add / remove, 409-aware), and source connections (add with kind-aware config, test, remove) for all seven source kinds. "Admin" added to the nav; API client + hooks for trucks/sources/events writes with a 204-no-body `request` path; client tests for create/delete/test. Frontend gates green: prettier, eslint, tsc, vitest 18 passed, `next build` ✓ (new `/admin` route). Live smoke verified: create truck, 409 on duplicate, add RTSP source, `test` config validation, rate-table PATCH.

### Changed
- **`GET /tickets` response shape:** now returns the `PaginatedTickets` envelope `{items, total, limit, offset}` instead of a bare `TicketOut[]`. Callers read tickets from `.items` and the full count from `.total`.
- **mypy config:** added a scoped override (`[[tool.mypy.overrides]] module = ["av"]`, `ignore_missing_imports = true`) for the optional, lazily-imported PyAV decoder (no stubs, not installed in the lint/type env); removed the now-redundant inline ignore in `app/pipeline/frames.py` and annotated a `monkeypatch` param in `tests/test_frames.py` to keep `mypy --strict` clean.
- **Database:** replaced the in-memory repository with a SQLAlchemy-backed one on a local **SQLite** file (`DATABASE_URL` defaults to `sqlite+aiosqlite:///./loadtruth.db`); set it to the `postgresql+asyncpg` URL to switch to Supabase Postgres with no model changes. Added `aiosqlite` dependency; ORM types made dialect-portable (`GUID`, `JSON`). `*.db` gitignored.
- Reconciled the `public.tickets` SQL schema (`infra/rbac/20_loadtruth_schema.sql`) to the §7a column shape: `est_*`, `monitor_*`, and persisted `delta_*` columns replacing the older `fill_pct`/`cubic_yards`/`rate`/`dollar_value`; ORM `Ticket` model aligned (text `debris_class`/`status` matching the SQL CHECKs, UUID `truck_id`). Fill-% values normalized to 2 dp.
- Added config `use_in_memory_repo` (serve the stack with no live Postgres) and the Next.js browser API base now routes through the `/api/*` rewrite.
- Agent protocol (`.kiro/steering/agent-protocol.md`): session-start now reads the architecture map first; added §4a (offload work locally to cut token usage) and §4b (agent- and code-level parallelism/multithreading).
- Made Python 3.12 the default for the user's shell via `~/.zshrc` (Homebrew `python@3.12` on PATH + aliases), without replacing the macOS system `/usr/bin/python3`.
