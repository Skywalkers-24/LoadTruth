### Added
- **Repeatable local benchmark batches and approved promotion.** Named runs support cache reuse or explicit fresh inference, concurrency up to five, no-replay checkpoints, interrupted-response recovery, cost/fill reports and local Postgres exports. A separate reviewed-bundle command can insert the selected event/tickets/evidence into Supabase transactionally after explicit approval; it refuses conflicting rows and never overwrites production data. See `scripts/README.md`.
- **Per-stage "AI analysis" is authored by Meta AI.** The Pipeline screen's "AI analysis" paragraph under each stage now comes from the model instead of a hardcoded client-side template. Muse Spark's OCR and classify calls each return an `analysis` string in their JSON schema (no extra call), and one batched text-only call (`explain_pipeline`, a new tunable AI task in the catalog with its own output cap) authors the analysis for the remaining stages (SAM track, capacity lookup, geometry, anomaly flags, valuation) from the run's measured facts. The paragraph flows end to end: `TrackResult`/`OCRResult`/`ClassifyResult`/new `StageExplanations` carry it, the orchestrator attaches it to each trace stage (`PipelineTrace.set_analysis`), it persists on a new nullable `pipeline_stages.analysis` column (added additively by `_add_missing_columns`) and round-trips through the AI-stage cache (`serde`), and both `GET /tickets/{id}/pipeline` and `GET /system/jobs` return it. The frontend renders `stage.analysis` and falls back to the composed client-side text only for older traces. Under `MOCK_AI` the mock authors the same grounded paragraphs so the demo path is unchanged. The analyst/narration prompts keep the no-dashes UI copy rule.

- **Demo video generation prompts (`docs/DEMO_VIDEO_PROMPTS.md`).** 24 full Google Flow / Veo prompts for 10-second gate-camera clips (fixed camera on top of a checkpoint gate, truck drives under, pauses so the top-down view can read the bed load and rear placard, then turns left/right out of frame). Adds a **five truck-type reference** (tandem, large tri-axle tandem, roll-off, walking-floor trailer, compact single-axle) with the certified capacities and real registry IDs from `backend/seed.json`, plus a fill-%-to-cubic-yards guide so each described load reads as a believable number. Includes a prompt index table and a recommended 3-minute demo order. **Realism pass:** the shared camera block now enforces a truly locked single-angle camera (no pan/zoom/dolly/orbit, no front-to-rear angle flip within a clip), a clean straight truck path that never clips cones or breaks the barricade, and a burned-in `CAM NN` + running date-time overlay so clips read as a real surveillance feed. **Corrected camera geometry:** the truck now drives *away* from a camera mounted high on the gate arch (rear/top three-quarter vantage) instead of toward it, because a front/grille view hides the two things the pipeline reads, the open bed (depth/fill) and the rear tailgate placard. All 24 scenario prompts were flipped to this away-from-camera framing, and the placard is specified in its real position (a white rectangular panel bolted to the center of the steel tailgate with a bold black truck ID) rather than a floating label. Added a **Lighting, depth, and the CCTV overlay** section (explicit day vs night lighting, steep look-into-the-bed angle with visible side walls and raking light so the fill-% estimator can read depth) and four **realism/camera-setup clips** (R1–R4: gate entry and overhead bed scan, each in day and night) with fixed save filenames (`cam01-gate-entry-{day,night}.mp4`, `cam02-bed-overhead-{day,night}.mp4`). **Anti-AI-tell pass:** eliminated the two cues that made generated clips look synthetic, non-constant motion (the truck stopping and rolling backward) and a morphing/popping placard. Every prompt now commands one constant slow roll in a single direction (no stop, reverse, speed change, or turn-out), exactly one rear-tailgate placard present and unchanged from the first frame with no second ID label, and only mild edge distortion with a slight corner vignette (no strong fisheye or dark porthole). **Prompts 1–24 are now fully self-contained:** each one independently states the high gate-arch camera mount and rear/top geometry, the steady one-direction motion, the load and its depth lighting, the single stable tailgate placard with its exact ID, the mild lens character, and a burned-in `CAM 01` + unique running timestamp, so no prompt depends on the shared block. Dropped the now-inaccurate "left turn / right turn" labels from the headings.
- **Server-side paging + sorting for the ticket ledger.** `GET /tickets` now accepts `sort` (`created`/`delta`/`measured`/`value`) and `order` (`asc`/`desc`) alongside `limit`/`offset`, ordering in SQL with null sort values (uncalled tickets have no delta) forced to the end in both directions and a stable `id` tiebreaker so pages never overlap. The Reports ledger drives its page and sort off the backend instead of fetching 100 rows and slicing/sorting in the browser (so it can walk every ticket in the chosen order); the admin "All events" view pages across the whole tenant.
- **Paginated AI pipeline jobs.** `GET /system/jobs` returns a `{items,total,limit,offset}` envelope and accepts `limit` (1-100) / `offset`, merging live in-memory traces with every ticket's persisted trace (de-duped by ticket) and paging the merged list on the server. The AI Pipeline screen pages through all jobs instead of only the first 50. `JobStore.capacity()` exposes the ring size so the full live window is read before paging.

### Fixed
- **A cached ticket that found no load no longer keeps a stale 0% fill.** Ticket LT-804655 (and any clip ingested before the load-concept changes) still read 0% even after the hazardous-load fix, because it was a cache hit: neither the per-clip Muse Spark load naming nor the new "barrels and containers" concept had run, and the offline re-measure path can only replay concepts SAM already returned (there was no load mask to replay). ### Added
- **Live pipeline progress, polled and refresh-safe, shown on the New Ticket page.** A clip used to run behind one blocking request, so the operator saw a generic "Analysing the clip" spinner for 30-40 seconds with no detail, and a page refresh mid-run showed a blank upload box. The pipeline now records each stage into a server-held snapshot (`ProgressStore`, the latest run per event) via an `on_stage` hook on the trace that ingest fires as each stage lands. `GET /system/events/{id}/pipeline-progress` returns that snapshot as JSON; the UI polls it every 3 seconds while the run is `running` and stops when it is `done`. The left-to-right stage flow (`LivePipelineFlow`) now renders on the New Ticket page (where the upload happens) as well as the AI Pipeline page, lighting up each step with its status and one-line result. Because the server holds the snapshot, refreshing the page mid-run re-reads the in-flight run instead of resetting. (This replaces the earlier SSE approach: polling is simpler, survives refresh for free, and needs no streaming connection.)

### Added
- **SAM load concepts are now named by Muse Spark per clip, not hardcoded.** Before segmenting, the live client asks Muse Spark to look at the load and return the noun phrases that describe it (for example "tree branches", "barrels and containers", "metal appliances"), then hands those to SAM. This removes the brittleness where a new debris type measured 0% until someone added a phrase by hand. SAM and the load-naming call no longer run fully in parallel (naming must precede segmentation), adding one Spark round-trip to the critical path in exchange for segmenting the right thing.
